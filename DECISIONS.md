# Decisions

- **2026-09-24: Build our own instead of using claude-in-mobile / mobile-mcp.** Both require adb pre-installed (neither downloads it), install via npx (needs the npm registry and a hand-edited MCP config), and neither ships as a one-click .mcpb. mobile-mcp also has telemetry on by default. We borrowed the good idea from claude-in-mobile: numbered element overlays on screenshots.
- **2026-09-24: Packaging = MCPB (manifest 0.3), Node, one bundled file.** Claude Desktop runs it with its own Node. Only pure-JS deps (no native modules), so there's nothing to compile and nothing needs admin.
- **2026-09-24: adb comes from Google's platform-tools zip, downloaded on first use to %LOCALAPPDATA%.** Download order is Node fetch, then PowerShell WebClient with the system proxy (for corporate proxies), then a manual path via the user_config override. The binary lives outside Dropbox.
- **2026-09-24: Wi-Fi pairing is the primary path.** It needs no USB driver, and OEM drivers (Samsung, etc.) may need admin.
- **2026-09-24: Coordinates default to screenshot-image space.** The server converts them to device pixels, and the element list omits device coords to avoid mixing the two.
- **2026-09-24: Filed under Personal MCP Development** per the Work Only MCP Dev rule that general-purpose tools live here, not under work/.
- **2026-09-24: No Bluetooth transport.** adb has none. BT PAN + tcpip is technically possible but too slow for screenshots, so it's documented and not supported.
- **2026-09-24: The isolated-network fallback is Windows Mobile Hotspot, not a relay.** It needs no admin and no infrastructure, but it bridges the wired LAN, so the README flags the IT-policy risk. Relays (Tailscale/SSH) are left to an IT conversation.
- **2026-09-24: The tool detects brand rather than asking first.** It asks only when detection fails. Samsung gets the explicit driver caveat.
- **2026-09-24: v0.3 ships a persistent on-phone helper (app_process + UiAutomation, no APK).** Measured cause of the slowness: `uiautomator dump` = JVM start (2.4-3.9 s on the S26) + idle wait. The helper cut screen reads to ~15 ms and screenshots to ~0.2 s. Fix 1 (caching and parallel calls) was dropped as pointless next to this. It connects with FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES so TalkBack and other accessibility services keep running, and it exits after 60 s idle because only one UiAutomation client can exist. It relies on hidden framework APIs (UiAutomation constructor, UiAutomationConnection), so it could break on a future Android version; the automatic fallback to plain adb covers that.
- **2026-09-24: Helper build = javac against hand-written stubs + Google D8.** No Android SDK install. The r8 jar lives in a Dropbox-ignored `.local-cache/`.
- **2026-09-24 (v0.3.1): Correctness fixes from live testing.** Typing inserts at the cursor via SET_TEXT + SET_SELECTION, treats hint text as empty, and hands password fields with text to the IME. Tap-by-text returns candidates on equal-score ties instead of guessing. launch_app waits for the package to be in front and has restart=true. Settle polls 15 ms screen reads until two reads match (max 2.5 s) instead of trusting UiAutomation idle, which returned before activity transitions started.
